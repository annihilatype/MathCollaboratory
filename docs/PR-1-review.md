# Дополнительная проверка PR #1

Проверено 12 ноября 2026 года, ветка `fix/v0.1.1-stabilization`.

## Найденные и исправленные ошибки

1. `ParameterControl` округлял подпись до восьми знаков после запятой. При `a = 3e-10` подпись показывала 0, хотя HTML range и вычисления использовали 3e-10. Теперь подпись выводит фактическое числовое значение, включая научную запись.
2. Проверка цвета в `decodeState` использовала неявное преобразование в строку. Объект цвета `{ "toString": null }` мог вызвать TypeError и общий сброс состояния. Теперь сначала проверяется тип; повреждённый цвет заменяется стандартным, остальные поля и записи сохраняются.

Математических расхождений в перечисленных пользователем выражениях не найдено. Изменений парсера и формата сохранения не потребовалось.

## Формулы и интерпретации

Все поддерживаемые случаи сравниваются с независимыми функциями `Math` при x = -3, -1, -0.25, 0, 0.25, 1, 2, 3 с точностью 11 десятичных знаков (`toBeCloseTo`). Невещественные и бесконечные результаты должны возвращать NaN как разрыв графика.

В таблице использована привычная математическая запись. Редактор MathLive передаёт степени в LaTeX, например `x^{2}`; тесты проверяют именно входной формат приложения.

| Ввод | Ожидаемая интерпретация | Результат |
| --- | --- | --- |
| sin x² | sin(x²) | Поддерживается |
| sin²(x) | (sin(x))² | Поддерживается |
| sin²(x + cos(x)) | (sin(x + cos(x)))² | Поддерживается |
| sin(x + 1)² | (sin(x + 1))² | Поддерживается |
| sin²(x² + 1) | (sin(x² + 1))² | Поддерживается |
| sin(-x) | sin(-x) | Поддерживается |
| sin -x | Естественное прочтение — sin(-x) | Отклоняется с просьбой указать скобки |
| -sin(x) | -(sin(x)) | Поддерживается |
| cos(x)^2 + sin(x)^2 | Тождественно 1 | Поддерживается |
| sin(cos(x²)) | sin(cos(x²)) | Поддерживается |
| sin(2x) | sin(2*x) | Поддерживается |
| 2sin(x) | 2*sin(x) | Поддерживается |
| (x+1)(x-1) | (x+1)*(x-1) | Поддерживается |

Дополнительно проверены:

- `-x² = -(x²)` и `(-x)²`.
- `2^3^2 = 2^(3^2) = 512` — правая ассоциативность степеней.
- `1/2*x = (1/2)*x` и `1/(2*x)` — разные функции, последняя не определена при x=0.
- `sin(x)^2` и `sin(x^2)` — разные функции.
- Несколько уровней вложенности, отрицательные степени, дробные степени десятичной записью и LaTeX-дробью.
- `sqrt(x)`, `ln(x)`, `1/(x-1)`, `1/0`, `0/0`: за пределами вещественной области возвращается NaN, а не фиктивная конечная точка.

Ограничения: `sin 2x` и `sin² x` требуют явных скобок; отрицательный аргумент без скобок также отклоняется. Обратные функции, комплексная арифметика и распознавание вещественных корней отрицательных чисел через рациональную степень не заявлены; вычисление степени использует числовую семантику JavaScript. Для расширения этого контракта нужны отдельные требования и тесты.

## Данные и параметры

Добавлены проверки повреждённой формулы среди корректных, старой формулы длиннее 500 символов, повторных id, ошибочного параметра, темы, строкового и объектного цвета, пустого списка и повторной сериализации. Корректные выражения и параметры сохраняются независимо от соседних повреждённых данных. В браузере смешанное повреждение проверяется на трёх последовательных загрузках.

Проверены диапазон с некратным шагом, отрицательные границы, дробные и очень маленькие шаги, значения вне сетки шага. Численное значение подписи совпадает со значением range и сохранением после двух перезагрузок. Вычисление `a*x` дополнительно проверено модульным тестом. Слишком мелкие непредставимые шаги по-прежнему отклоняются.

## Интерфейс и настоящий ввод

Повторно проходят проверки Tab, Shift+Tab, Escape, отмены и подтверждения сброса с возвратом фокуса. Проверены удаление первой и средней функции, а также перестановка существующих редакторов и их доступные имена.

Дополнительный тест нажимает на MathLive, дожидается фактического DOM-фокуса, вводит `x+1` событиями клавиатуры, редактирует через Backspace до `x+2` и вставляет 501 символ через буфер обмена / Control+V. Вставка отклоняется с сообщением; предыдущая формула сохраняется после перезагрузки. Это устраняет прежний пробел в проверке реального ввода. Вызов `focus()` у MathLive сам по себе не означает, что браузер уже перенёс DOM-фокус: ранние тесты отправляли символы ещё на кнопку добавления.

## Архитектурная оценка normalizeFunctions

Текущий конвейер: ограниченное преобразование LaTeX → нормализация записи функций → `mathjs.parse` → проверяемый AST → собственный ограниченный вещественный вычислитель. AST уже существует: его создаёт mathjs. normalizeFunctions — небольшой адаптер входа, а не полноценный математический парсер.

Для фиксированного набора функций v0.1.1 он достаточен: разбирает сбалансированные скобки и отличает степень аргумента от степени функции. Для долгосрочного ввода уровня Desmos он не должен расширяться бесконечной цепочкой правил. Сейчас токенизация, разбор LaTeX, неявное умножение и приоритеты распределены между несколькими слоями. Пробелы и исходная форма записи частично теряются, нет диапазонов исходного текста для точной диагностики, неоднозначность разрешается локально. Есть ограничения 500 символов и 150 узлов; поддерживаются только вещественные функции одной переменной и однобуквенные параметры с индексами.

Переход к единой грамматике входа целесообразен до добавления нескольких новых взаимодействующих конструкций: неявных произведений внутри аргумента, обратных функций, корней произвольной степени, вложенных модулей, более общих имён и точной диагностики неполного ввода. Не нужно создавать второй вычислительный движок: использовать существующие узлы AST mathjs, сохраняя allowlist узлов и функций; нормализатор должен строить однозначные узлы вместо переписывания строк. MathLive остаётся редактором LaTeX. Для будущего расширения можно расширять существующий проверяемый обход mathjs AST, не передавая произвольные выражения в небезопасное исполнение. Крупный рефакторинг в PR #1 не требуется.

## Проверки и решение

- 106 модульных тестов (включая 42 новых теста этого этапа).
